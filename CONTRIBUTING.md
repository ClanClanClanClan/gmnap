# Contributing

Thanks for your interest in working on **MathLineage / GMNAP V7**.
This document collects the actual rules CI enforces so a new
contributor can land a PR without trial-and-error.

## Setup

One-time, on a fresh clone:

```bash
git clone <repo> gmnap && cd gmnap
git lfs install && git lfs pull        # pulls data/genealogy_enrichment.json (~6 MB)
make setup                              # pip install + compile fasttext + install git hooks
```

`make setup` triggers four things:

1. `pip install -r requirements.txt` (runtime deps)
2. `bash scripts/install_fasttext.sh` (compiles the fastText CLI; soft-fail if the toolchain is missing — the system still works rules-only)
3. `bash scripts/install_hooks.sh` (copies `scripts/git_hooks/pre-commit` to `.git/hooks/pre-commit`)

For the dev/test toolchain (Playwright, pytest-cov, etc.):

```bash
pip install -r requirements-dev.txt
playwright install --with-deps chromium    # for tools/browser_smoke.py
```

Reproducible install matching CI exactly:

```bash
pip install -r requirements.lock
```

Lock is regenerated by `make lock` (uses `pip-compile`); commit both
`requirements.txt` and `requirements.lock` in the same change.

## Running tests

The CI test job's exact pytest invocation is reproduced under the
`Core tests` step in `.github/workflows/ci.yml`. To run it locally:

```bash
PYTHONPATH=. pytest tests/unit/ tests/authority/ tests/cjk/ tests/db/ tests/v7/ tests/integration/test_memgraph_e2e.py \
    -v --tb=short --timeout=120 -p no:cacheprovider
```

Property tests:

```bash
PYTHONPATH=. pytest tests/property/test_unicode_properties.py \
    -v --tb=short --timeout=120 -p no:cacheprovider
```

A handful of test directories (`tests/coherence/`, `tests/compliance/`,
`tests/idempotency/`, `tests/genealogy/`, `tests/memory/`,
`tests/mock_api/`) have known failures and are excluded from CI.
The triage report is at `docs/test_triage_2026-04-28.md`.

### Coverage

CI runs a separate `coverage` job that exercises a curated subset
of `tests/unit/` under `pytest --cov=src --cov-branch`. The floor
is **`--cov-fail-under=15`** (combined line + branch). To run
locally:

```bash
PYTHONPATH=. pytest tests/unit/test_calibration.py tests/unit/test_pipeline.py … \
    --cov=src --cov-branch --cov-report=html
open htmlcov/index.html
```

The full curated list lives in the `coverage` job in
`.github/workflows/ci.yml`. Don't drop the floor without a
documented reason in the commit message.

## Lint and formatting

CI's `lint` job runs four tools. Run them all locally before
pushing:

```bash
black --check src/ tests/
ruff check src/ tests/
isort --check-only --profile black src/ tests/
```

`make lint` does black + ruff + isort + yamllint in one shot. Pinned
versions in CI:

| Tool | Version |
|---|---|
| black | 26.3.1 |
| ruff | 0.15.8 |
| isort | 6.0.1 |
| codespell | 2.4.2 |
| yamllint | 1.38.0 |

The pre-commit hook (`scripts/git_hooks/pre-commit`) does three fast
checks:
1. E4 Korea region loads cleanly.
2. All 37 regions load in under 2 s.
3. **`tools/audit_repo.py --fast`** — 16 of the 18 repo-invariant
   checks (skipping the two subprocess-spawning slow ones, B2 and
   I1, which CI runs in full). Catches the kind of drift the audit
   was built for: references to deleted files, JSON/YAML parse
   errors, doc-vs-data numerical claims, test-module shadowing,
   etc. — before they reach CI.

If you genuinely need to commit past the hook, `git commit
--no-verify`. CI runs the **full** audit (18 checks, 8 jobs) on
every push regardless, so a bypassed hook just delays the failure
to push-time.

## Branching and PR style

- Open PRs against `main`. There is no `develop` branch.
- One topic per PR. If you find unrelated cruft mid-change, file a
  follow-up rather than mixing it in.
- Commit messages use the conventional-ish prefix style the repo
  history already uses: `feat(area):`, `fix(area):`, `chore(area):`,
  `docs(area):`, `ci(area):`, `perf(area):`, `style(area):`.
- The body of a commit message should explain **why** the change was
  needed, not just **what** was changed.
- All PR commits should pass CI green. Don't push if your last commit
  failed — fix-forward with another commit; never amend after pushing.

## What CI runs on every push

8 jobs, all gated:

| Job | What it checks |
|---|---|
| `lint` | black, ruff, isort, codespell, yamllint, lockfile-in-sync |
| `test` | full pytest invocation (~50 files, including property tests) |
| `coverage` | curated subset under `--cov=src --cov-branch --cov-fail-under=15` |
| `secret-scan` | TruffleHog with `--only-verified` |
| `cost-guard` | API spend < CHF 120/month |
| `docker-build` | image build + smoke-test on `/healthz` + `/readyz` |
| `memgraph-test` | full live-Memgraph integration via GHA `services:` block |
| `browser-test` | 31-scenario adversarial Playwright harness against real Chromium |

Every job must be ✅ for the PR to merge.

## Reviewer-facing docs

Before opening a PR, skim:

- `ARCHITECTURE.md` — five design decisions an evaluator asks about
- `DEMO.md` — 10-minute reviewer walkthrough, CLI / web / API
- `docs/calibration.md` — confidence calibration methodology + numbers
- `docs/perf_characterization.md` — measured 1M-scale throughput
- `docs/api_reference.md` — every endpoint, params, responses (auto-gen with `make api-docs`)
- `docs/test_triage_2026-04-28.md` — which non-CI tests pass and why others don't
- `CHANGELOG.md` — running list, Keep-a-Changelog format

## Reporting bugs and security issues

For non-security bugs: open a GitHub Issue with reproduction steps,
expected vs. actual, and the relevant `pytest -v` output if you can
get one. Tag with `area:<region|api|cli|pipeline|…>` if obvious.

For security vulnerabilities: see `SECURITY.md` for responsible
disclosure. Do **not** open a public issue — email the maintainer
directly.
